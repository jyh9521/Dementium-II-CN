# 明信片图文重叠修复（2026-10-21）

## 症状与根因

用户实机截图中，EN/EXAMINE.041 第一行盖住明信片。不是字库解码问题。

**静态确认：** `FUN_14011a6f0` 在找到检查背景时设置文字控件 `(0,104,256,72)`；
绘制首行 y 为 `72 + line_spacing - (linefeed + line_spacing) * measured_lines`。
字体构造器 `FUN_1401109d0` 在 +0x88/+0x8c 初始化字距1、额外行距0。
当前 linefeed=16。旧版实际7行（含段落空行与尾部空行），首行 y=-40，超出文字纹理上边界。
额外前导空行会被底部对齐计算抵消，不是有效的定位修复，因此最终配置没有加空行。

静态证据：
- `ev_b8edfee30173ee66d75fca9e21695000702420330c094e09e91fc79126783ab3`：检查界面。
- `ev_64516d0c2e95747372dfbecc62ecb31a5cc4a9b381e253b0557d970c7617c3f7`：收藏明信片使用相同72px底部对齐公式。
- 本地证据：`build/evidence/postcard-0x14011a6f0.json`、`postcard-0x140121d90.json`。

## 修改

- `font-profile.json` 为12个明信片资源单独设置228px宽、72px高、最多4行。
- `font_pipeline.layout_document` 重排明信片软换行和空段落，保留引导语、引用内容、独立署名及控制变量。
- 引导语压缩为“天堂寄来的明信片，上面写着：”；045压缩句式，保留逃离已晚、回监狱阻止他、匕首变量和署名。
- 字号仍为 Fusion12，不修改 EXE、图画、全局行距或其他107个调查资源的排版规则。
- 超过行数、宽度或实际测量高度时拒绝构建，不截断或静默删字。
