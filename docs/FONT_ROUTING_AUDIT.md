# 双字体资源路由静态审计

日期：2026-10-21。对象为 supported-build.json 锁定的原生 x64 Steam 构建；EXE SHA-256 为
`b71ce6d2d803a7ded50c07c5ca918658fb0b1423db68bbc31129c257909123c2`。
本审计只读取既有提取与 REA 缓存，没有启动游戏、修改 EXE 或重做整体引擎调查。
用户已提供“新游戏”实际显示截图；该截图验证既有最小链路，不等于本次双字体和全量排版验收。

## 结论

**High-confidence deduction：推荐保留一个主图集，普通 BMP 中文追加 Fusion Pixel 12px，
明确选中的章节标题中文映射到 BMP PUA 影子字形，追加 ChillBitmap 16px。**
这是构建期、可逆的显示编码转换，不是把译文源文件写成私用字符；译文仍保存真实中文。
原 Latin、数字、装饰符字形元数据与原图集像素原样保留，DEBUG08 不改作大标题字体。
字形来源、字号、PUA 映射和字段/片段选择规则须进入 locale 配置与构建报告。

该路线有直接的静态尺寸/查字证据，但**16px 标题实机裁剪、基线、双行章节间距仍待画面验证**。
单一 atlas 不等于只能使用同一字库或同一字形尺寸。

## 1. Verified / 静态：每字形尺寸，不按 cell 强行裁切

`build/evidence/0x140111890.json`，函数 `FUN_140111890`，证据
`ev_2953f623dbbf93b0929d3908bf98c98fd42c1089e7a7369f069cb1bb04f683e4`。

此函数的反编译省略了部分传给 SpriteMachine 的浮点参数；**应以同一证据的 assembly 为准**：

| 地址 | 读取/行为 |
|---|---|
| 0x1401118ab | 调用 glyph lookup 0x140111740 |
| 0x140111a18 | glyph+0x18（yo）与调用方 y 相加 |
| 0x140111a1b | glyph+0x1c（h）转为浮点 |
| 0x140111a22 | glyph+0x10（w）转为浮点 |
| 0x140111a27 / a2c | glyph+0x8 / +0x4（ty / tx） |
| 0x140111a35 / a3b | glyph+0xc（xo）与调用方 x 相加 |
| 0x140111a7a | 把逐字形坐标/宽高传给 0x1401a6ae0 |

此绘制路径未读取 font.cell_width / cell_height 作为逐字裁切上限。
因此在同一 atlas 放入 w/h=16 的有效字形有代码依据；必须同时检验 atlas 边界和渲染目标区域，
不能由此推出按钮纹理、文档视口和上下裁剪框都可自动增长。

解析器 `FUN_140110e00` 见 `build/evidence/0x1401114b4.json`，证据
`ev_3cb848e5c3415a370f8874fa6aba3fe1d84f115caab8d9c72d45cec3211179be`。
解析器分别读取全局 cell、layout、linefeed 和逐字形属性，数字键保留低 16 位。
PUA 使用 U+E000..U+F8FF，须检查原图集、实际译文及其他映射不占用目标码点；
拒绝非 BMP 字符、重复映射和容量溢出，不使用增补平面 PUA。

## 2. Verified / 静态：宽度和按钮路径支持 PUA，不支持统一字体控制码方案

`FUN_140111740` 按 ushort 查询哈希表，失败回退码点 0。
`FUN_140111b60` 解码 1/2/3 字节 UTF-8，按 glyph+0x14（logw）与 font+0x88 字距累计宽度。
见 `build/evidence/0x140111740.json`、`0x140111b60.json`；宽度证据
`ev_af3dacf304016bd373534c57bb34bad120655976f83e037652d44813da0bc1b3`。
BMP PUA 三字节编码会走同一条查字/测宽路径；Chill 字形配置 logw=16 会进入实际累计宽度。

`FUN_1400af860`（dsButtonText::Refresh）也逐 BMP 字符查找并累计 logw，绘制时调用同一 glyph draw。
它用 glyph.xo 和 glyph.w 计算水平外接范围，但本缓存没有证明渲染目标的高度会随 glyph.h 增长。
此函数**没有** 1..8 控制码切换分支；不能给所有按钮注入 7/8 后声称可切换字体。
证据 `ev_88ede185bda91b6ac465dc2b969e2619f9cc72275a69931689b4f65dc8db28d8`。

按钮文本起点+0x40 是字体指针，仍仅提示可能存在 64 字节内联区域。
缓存中的 `button-constructor.json` 实为 0x1400af400 的状态刷新，不是复制文本的真正构造函数；
不能据文件名推断已经确认 strcpy 或 63 字节上限。
固定菜单可采用 UTF-8 字节风险告警，但所有资源的容量字段应继续区分 unknown 与已证明上限。

## 3. DEBUG08 路线比较

初始化 `FUN_1400a72e0` 加载 main `/fonts/d2font_12x15` 和 debug `/fonts/debug08`，默认字体为 main。
文本绘制 `FUN_1400b05c0` 中：6 选择 singleton+0x50 main，7 选择+0x58 debug，8 选择+0x60 default；
1..5 是颜色，不能把章节现有 3/2 当作字体标记。
证据 `ev_bce1fd406cce3d62a4f2a5dd986b339b56797451deaf7f8e8baa797cc1030d6e`。

| 路线 | 收益 | 风险 / 取舍 |
|---|---|---|
| main 普通中文 + PUA 标题 | 不改原控制码；按钮和普通文本均走已有 BMP 字形测量；保留 DEBUG08 | 需明确、可逆的 locale 映射；单字体全局行距不能逐 PUA 自动改变 |
| DEBUG08 改为 Chill16 + 注入 7/8 | 普通文本绘制已有双字体开关；字体全局度量可分离 | 按钮路径不解释开关；可能影响未调查的原 debug 字体用途；原 debug Latin 是 8px 而非 main Latin；注入控制码还会改变 token 序列 |
| 新增第三 JSON/PNG | 概念清晰 | 只加资源不会自动实例化新字体；既有初始化没有第三加载路径，需要另行 EXE/运行时工作 |

本增量阶段不建议牺牲 DEBUG08，也不需要为解决两个已知开源字库的资源组合先修改 EXE。

### 字库覆盖例外

构建器允许 Fusion 缺字而 Chill 已覆盖时，按真实 Unicode 码点追加正文回退，与标题 PUA 映射分开。
2026-10-22 已修复旧实现把原生 16px、yo=-2 标题字形直接混进正文的问题。
当前所有正文补字按 body.pixel_size=12 栅格化，w/logw=12、h=15、xo/yo=0；
按 body ascent - fallback ascent 在字形格内部补偿，本机 13-11=2px，使字形基线一致，
并保留原正文行距 16px。独立标题 PUA 仍使用 16px、yo=-2，不缩小标题。
当前全部 676 条文本、预览及额外 UI 字符扫描发现仅 U+8F98 辘、U+9AB6 骶 两个正文补字。
两个字体都缺字或按共同基线移位后越格时构建失败，不裁掉字形、不替换译文。
`body_fallback_native_pixels` 记录来源标题角色的原始规格；`body_fallback_pixels` 才是正文实际栅格尺寸。
`body_fallback_baseline_shift` 记录格内基线补偿，不是运行时 yo。
合成 TTF 回归包含非零 ascent 差和逐像素一致性；完整构建自动调用 audit_body_fallback.py，
复核全部补字的字库覆盖、元数据、实际 PNG alpha 以及逐条文本来源，并输出图集直取预览。
离线证据见 build/fallback-font-fix/VERIFICATION.txt；不等同于游戏内画面验收。

## 4. 全局度量与换行边界

原 main：cell_width=12、cell_height=15、layout_height=8、layout_top=5、linefeed=13。
`FUN_1400b05c0` 的 LF 前进量由所选字体 linefeed 与调用方行距组成；对 glyph.h 没有动态取最大值。
垂直范围早退读取字体 cell_height（font+0xc）的低字节，不读取当前 glyph.h。
因此 16px 字形可能超出早退近似边界，尤其是 yo 为负、标题位于视口边缘时。

`FUN_140111b60` 的多行高度按 (font.linefeed + font+0x8c) * 行数 - 尾部间距计算。
将 linefeed 从 13 改 16 会影响**所有**主字体多行测量/排布，而不是仅 PUA 标题。
保留 layout_height/top 能减少更广的度量变更，但不是垂直居中、视口或按钮高度已兼容的证明。
可通过离线墨迹外接框测试发现重叠，再用真实章节画面检查上下裁切与两段间距。

**Verified / 静态：**缓存中的 `FUN_1400b05c0`、`FUN_140111b60`、`FUN_14011ef50` 仅见 LF 分行，
没有依据当前 x 超过行宽自动换行的分支，也没有已证明的按空格分词断行函数。
这不排除上层调用方预排版；缓存尚未定位完整文档上层流程。
不应把“未见 CJK 自动换行”写成“已确认原生按英文空格自动换行”。

EXAMINE 本来就有 CRLF/LF，构建期按实际 logw 预排版是合理增量；
应保留段落/控制码/变量，避免把多字节 UTF-8 切开，并单独报告预排版后行数。
TBL/SUB 的物理行是格式，不可直接插入 LF 改变记录；`|` 的数量与位置规则保持原合同。
自动预排版只能称离线验证，不替代页高、滚动、字幕时长或游戏全流程验收。

## 6. 离线保守门禁（配置约束，不是反向证明的真实框尺寸）

- 章节第一段可先设 192 逻辑像素检查上限，12 个 16px 字以内；
  这只是短标题工程预算，不声称已确认章节框宽=192。
- 正文可先设不超过 216 逻辑像素，即最多 18 个全宽 12px 字，再计原 Latin 实际宽度和字距；
  长度较小也不意味着所有交互提示/列表控件都适配。
- 可变变量需显示“运行时展开宽度未知”，不可只测 `$Keypad,...$` 字面值后当作最终宽度。
- 每个标题实际墨迹框、advance、上下留白、控制码零宽处理、映射唯一性要有测试。
- 不提高原 atlas 宽度而仅向下追加可保留原像素位置；若调整宽度，tx/ty 仍可保留，
  但要验证原区域逐像素相等。512×不超过4096 的图集属于构建预算，不是已证实的 GPU 最大纹理尺寸。
- 二次提取需先逆映射 PUA 再与真实目标中文比较，同时保留原始导出用于审计。
- PUA 逆映射只适用于本构建 manifest 指定的资源/片段，不能全局替换未知来源私用字符。
