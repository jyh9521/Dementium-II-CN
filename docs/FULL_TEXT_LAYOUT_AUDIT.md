# 全量文本换行核查（2026-10-21）

## 边界与逐条台账

本轮检查全部179个可见英文文本资源的676条记录，而非只检查实机截图或18篇散文名单：

|类别|记录数|处理|
|---|---:|---|
|调查/物品/信件/墓志铭等EXAMINE|119（含12张明信片）|逐物理行宽、短尾、禁则、高亮完整性和明信片行高检查|
|表格|465|逐显示段宽度、控制码与`|`顺序检查，保留一行一记录|
|字幕|82|逐显示段宽度、控制码、`|`顺序及帧时间前缀检查；含6条帧率头|
|交互|10|宽度、控制码检查，不新增未经验证的交互换行|

`tools/audit_text_layout.py` 输出逐条 ledger，并在任何记录缺失、越预算、生成短尾、高亮词被换行拆开、禁则错误或保护标记损坏时返回非零。
`build/full-layout-audit/text-modified-audit.json` 保存本地编译审计，最终集成构建应再次调用该工具复核真实输出ROM。

## 基线发现和修复

旧中文ROM的全量门禁产生22项问题，涉及16条记录：041、045、051、078、090、093、503、510、520、521、530、533、541、544、574和OPEN.010。
这些涵盖短尾、高亮拆词、标题大段排版空格以及一个交互提示超宽；不只是504截图便条。

- 为全部119篇EXAMINE启用locale配置的52px最短自动折行尾段预算。独立标题、药物名、“我”等源译文有意独立的短行仍保留；不把短标题拉入正文。
- 明信片041/045/051的短尾也修复，保留原有4行/72px门禁，不放宽框体高度、不删正文。
- 原生02/01强调控制对里的可容纳短词（例如“匕首”）作为排版原子，避免把前后汉字拆到两行；控制码序列不变。
- 530保留4行故意错落、分散的文字及段落，只收紧过宽空格并保留缩进，防止额外把“点”折出去。522诗歌、535字母谜题、545断裂式独白不被重排合段。
- 541/544标题与页码间原有20多个排版空格改为一个空格，保持书名、页码和正文完整。
- OPEN.010删除冗余“上面”，259px缩至233px（预算240），不增加交互资源物理行。

新编译文本与上轮相比，只有上述16条实际输出发生变化。其余记录接受了检查但未为凑数量而修改。

## 验证命令与结果

基线：

```powershell
python -X utf8 tools/audit_text_layout.py --archive build/text-layout-fix/modified/rom.zar --logical build/text-layout-fix/modified/text.json --output build/text-layout-fix/full-text-baseline-audit.json
```

字面输出：`FULL_TEXT_LAYOUT records=676 resources=179 issues=22 affected_rows=16 variable_rows=9 runtime=UNTESTED result=FAIL`，退出1。

修改后以`build_mixed`真实编译、`import_text`回填、`Zar.rebuild`重建及`extract`二次提取后调用同一审计：
`FULL_TEXT_LAYOUT records=676 resources=179 issues=0 affected_rows=0 variable_rows=9 runtime=UNTESTED result=PASS`。
6项新增合成回归测试加既有测试，共129项通过。

## 验证层级

这是全量资源的离线排版核查，不是所有场景/字幕时长/运行时框高均已实机通过的声明。
228/240px是项目工程预算；12张明信片另有已定位的72px真实框高。
9条含动态变量的资源仍依赖运行时展开结果，审计明示`RUNTIME_PENDING`；24px变量估宽不冒充所有键帽或谜题展开的真实宽度。
图片标签和5条EXE文字由集成构建的图片核查及既有EXE守卫另行验证，不计入这676条。
