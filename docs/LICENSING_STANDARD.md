# Component Inventory and Attribution Standard

The actual terms and authorship remain in [LICENSING](../LICENSING.md) and the existing formal notices. This migration does not replace a license, attribution or redistribution decision.

## Component and release inventory

For each bundled component record path, source URL, author, version/commit, license identifier, notice location, modifications and redistribution decision/evidence.
Track code, fonts, tools, documentation, translation, image layers and generated media separately.
For mixed translation files, identify source text versus contributor translation; a project license grants no rights over the underlying game content.
For generated outputs, inspect their contents and input terms; generation alone creates no blanket redistribution permission.

Prefer transformations and locally generated payloads when original game assets must be supplied locally.
Do not commit complete proprietary executables, archives, media or fonts without explicit permission.
Apply the same inventory to releases and CI artifacts, not just the Git repository.
Keep attribution in a shipped notice file where required. Document uncertain components rather than marking them redistributable by default.

## Upstream and contributions

Preserve upstream notices and compatible licensing, including source-available/EULA terms where applicable.
Record what was reused and independently verified; credit technical discoveries as well as code.
Contributors follow the license for the relevant material as described in the formal files.
Add project-specific exceptions by path/material and governing notice, without suggesting that local wording overrides third-party rights.
