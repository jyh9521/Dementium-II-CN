# 本次已遇到的问题（2026-10-21）

## ZAR TOC 与 VFS ~INDEX 必须同步（Verified）

用户启动实验版时主字体 PNG 报 STB 加载失败。原因是外层成员已变长，VFS 仍按 ~INDEX 的旧长度分配读取缓冲区。
此前完整 PNG 解码和封包解析均通过，未能检测真实读取路径中的截断。
已添加双索引同步及回归；证据、失败样本和排除对齐假说的实验见 [STARTUP_FONT_FIX.md](STARTUP_FONT_FIX.md)。

## 干净检出的换行使发行 ZIP 哈希不同（Verified）

首次干净源检出重建得到相同 rom.zar 和 patch.json，但 ZIP 哈希不同。
逐成员检查发现 supported-build.json 的本地 CRLF 与检出 LF 是唯一内容差异。
修复为生成 JSON 固定 LF，并在文本白名单打包时统一换行；新增两个回归测试。
须分别验证资源、差分和最终发行包的复现性，不能只比较其中一项。

## CP932 默认编码会破坏带重音原文（Verified）

实验准备脚本曾使用未显式指定 encoding 的 Path.read_text，导致三条制作人员姓名被错误解码。
源字段校验以 Stale source/location 拒绝输入，未生成该损坏输入的补丁。
修复为 encoding='utf-8'，新增带重音 JSON 往返回归测试；命令示例使用 python -X utf8。

## 游戏启动与离线工作分开

前轮曾启动原版副本，用户明确要求不擅自启动；后续仅离线分析和构建。
工具不含游戏启动代码，原版截图不是中文显示验收证据。

## 外层可变长不代表内联文本容量已验证

按钮刷新结构在文本起点 +0x40 读取字体指针，复制容量路径仍待查证。
长文本样本仅用于离线准备，不作为已兼容菜单的发行内容。

## 2026-10-21 Material安装器迁移（已验证）

- 旧WinForms依赖系统.NET Framework，不满足无需另装运行依赖。新WPF使用自包含发布并嵌入原生运行库；代价是EXE约74MiB。
- MaterialDesignThemes 5.3.2 的MaterialDesign3.Defaults仍使用MaterialDesignRaisedButton / FlatMidBgButton等样式名；不存在FilledTonalButton键，需建立基于真实样式的别名，不能凭名称猜测。
- 同目录两个csproj需不同MSBuildProjectExtensionsPath和锁文件，否则Tests恢复会覆盖安装器NuGet资源/锁文件。使用提前导入的Directory.Build.props分离中间目录。
- 不给整个项目设置RuntimeFrameworkVersion来锁.NET版本：Windows SDK引用也会误用10.0.13并恢复失败；记录SDK10.0.402和运行时资源实际身份、锁定工具包输入。
- Steam库路径比较必须规范化分隔符；安装目录来自ACF的installdir，不来自写死的common/Dementium II。
- Material按钮内部含默认不可见的进度控件，UI检查应检查可见实例，而非把内部模板当作用户线性进度条。
- RenderTargetBitmap拍子树时不继承Window背景，需在预览绘制中先填充与Window一致的底色，避免透明区域预览成黑色；该修复不修改品牌PNG。


## 2026-10-21 新Steam build导致原版验证失败（已修复）

Steam本机清单26099941与原补丁26091059不同，不能只替换ROM哈希：新EXE大小和.rdata槽位置也变了。
新HI-RES CRT槽由16缩至12字节，且排列移到HI-RES后；必须核对完整源字符串/零填充及邻接数字1。
差分生成器现在按offset规范化条目，避免语言配方顺序变化生成乱序runs被原生安装器拒绝。
120项Python测试中包含乱序配方生成规范差分与双向恢复回归；版本元数据/界面标签一致性也增加测试。
安装器实际目标路径使用只读--inspect验证；只在复制出的真实文件上安装和恢复。


## 资源级兼容与恢复

删除整包SHA门禁并继续使用绝对偏移不是兼容方案。资源级实现解析当前TOC/VFS、使用实际EOF追加，并在当前EXE的.rdata唯一匹配字节槽。
不对未知目标内容猜写；不相关更新与待改资源内容更新须分开处理。
备份名绑定实际输入而非构建参考；多次Steam更新不得覆盖先前备份，恢复必须选择这一次安装所记录的原件。
整包SHA仍用于备份完整性与并发变更检测，不用于判定Steam版本。

## 整图美术导入与原生调试字体（2026-10-21）

整图art_delta分支会绕过原像素保护/文字框重建；控制示意图不可用整图再生成替代原按键、方向箭头、连线、边框或alpha。此轮12图恢复原图像素并加入文字区外一致性门禁，见NATIVE_UI_IMAGE_REPAIR.md。原生ImGui字体必须同时替换TrueType轮廓字体和ASCII范围；仅换文件仍会漏掉中文。字形验证必须包含cmap、实际轮廓及可见墨迹，见NATIVE_CHEAT_MENU.md。

## F1直接输入门禁遗漏（2026-10-21）

原生启动会把输入对象+458置零。只测启用模式、手工输入键状态再回放菜单边沿，会漏掉真正的事件失效。回归必须串接原生启动模式分支、键码翻译、按下/松开包装器和vtable处理器，见test_debug_dispatch.py。

SIGN_02的D.R.格此前在排版审计中误列restore_source_regions，导致翻译被回退。按用户要求统一死囚区，撤销英文恢复保护，以单格精绘导入并锁定双轴墨迹居中；其他格像素保持上一版精确不变。

## 菜单可见不等于拥有输入（2026-10-21）

F1开关、角色操作屏蔽、平台cursor可见性/捕获及ImGui滚轮输入是不同路径。只验证visible分支不证明光标出现或滚轮/键盘可用。回归应串联实际PE入口，并覆盖两种+458模式、滚轮消费优先级、F1到定位/限制、失焦释放、关闭恢复及重定位；Win32边界替身与真实窗口观察须分开记录。

长文恢复原分行后不得继续沿用“合并软换行消除短尾”的旧策略；应保护标题/空行/缩进并在专用阅读器滚动。字体元数据/图集、明信片、谜题和非文档UI必须与修复前逐字节比较。

## 指针边沿与控件激活不是同一验收层

仅排队 WM_MOUSEBUTTON 并验证 ImGui MouseClicked 不足以证明按钮可用：实际游戏输入轮询会在绘制菜单前重写 +231/+232。必须包含轮询、Checkbox/按钮激活、真实动作队列消费；关闭/失焦还须覆盖按住时取消，防止重开菜单触发幽灵点击。
复制 RIP 相对指令时必须从受守卫的原始指令解码 next-IP+displacement。现场文本门禁4c21ff与调试关卡名4c2200相邻，错写一个字节会同时造成缺字和下次开局加载非法关卡。文本验收必须跑过字形提交门禁，并断言相邻状态不变，而不只是检查坐标和行片段。

## “WndProc”必须追到实际注册入口；借用输入模式必须对称释放

窗口类注册的是2f3650，再进入2f3900；旧回放直接进入2de7a0 common handler，漏掉2f39cc首次点击捕获并返回的外层分支。完整消费者回放通过也不能证明事件从注册入口可达。诊断必须保留实际注册入口和回调链，不应把内层translator称作完整Win32入口。
输入+458为0时，阅读器绕过全部按键门禁会令关闭前E down写+227、关闭后E up却不写字段。只观察listener收到keyup会误判成功。必须限定借用键种，并用普通游戏动作上升沿而非仅reader_active=0验证释放。

## 输入释放必须覆盖所有退出与焦点边界

只测close会漏掉render inactive和open重初始化；也不能无条件清从未归阅读器所有的游戏键。失焦清逻辑字段后，Win32 VK防重复数组与F1消费者previous仍可能保留，导致首次新按下被吞；只清这些状态又会把恢复焦点后的自动重复误当成新按下。回归必须同时包含外部松键与物理仍按住两种时序，并包含二者之间没有渲染帧的情况。

## 库存短信用空白填充不能作为溢出正文

EXAMINE.092/093的原生5行计数包含末尾空行；实际可见正文只有4/2行。不能直接按原生总行数开启滚动，也不能删原文空段或回退坐标导致文字压到图片。库存图文信件仅用最后非空内容行计算滚动范围，保留源字节、内部空行、既有绘制锚点；现场和其他物品不变。

## 补字来源不能继承标题尺寸与原点（2026-10-22）

字库cmap覆盖不代表混排正确：Fusion12缺少辘、骶，旧实现直接借用Chill16并设yo=-2，导致两字大于正文且上凸。必须分离来源face与排版role，按body字号栅格化，再按ascent差对齐正文基线；不能仅把w/logw改小而保留16px像素，也不能只改yo。回归同时检查元数据和实际alpha。
