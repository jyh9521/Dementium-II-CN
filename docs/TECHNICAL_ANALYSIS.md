## 2. 引擎判断

**Verified / 静态：**安装目录包含 `spiller.toml.readme.txt`，说明此构建使用新的配置系统；EXE 内有 `spiller.toml`、`game_spiller.toml`、`spiller.log`、`D2Presentation`、`SpriteMachine`、`dsButtonText::Refresh` 等字符串。
源码路径常量指向 `C:\rg\d2\build_gdk_steam\Gaming.Desktop.x64\Release\Dementium II.pdb`。
资源是可直接读取的 ZAR1 成员，主字体由 JSON/PNG 组成。

**High-confidence deduction：**当前构建采用以 Spiller 命名的原生运行框架，并保留 DS 时代数据和自研游戏组件。
没有依据将其归为 Unity、Unreal 或 GameMaker；未对其完整谱系或是否包含模拟层作结论。
NFTR 文件存在不代表当前 PC 主字体仍由 NFTR 渲染，实际初始化代码加载的是 JSON/PNG 字体。

## 3. ZAR1（Verified / 静态＋全包解析）

全部整数为小端。头部 0x20 字节：

| 偏移 | 类型 | 本机构建值 | 含义 |
|---|---|---|---|
| 0x00 | char[4] | ZAR1 | 签名 |
| 0x04 | u32 | 3471 | 条目数 |
| 0x08 | u32 | 0x100000 | 预加载头部大小 |
| 0x0c | u32 | 0 | 未知，原样保留；工具拒绝非零变体 |
| 0x10 | u32 | 0x20 | 名称偏移数组绝对位置 |
| 0x14 | u32 | 0x365c | 名称池绝对位置 |
| 0x18 | u32 | 0x15e70 | 成员描述数组绝对位置 |
| 0x1c | u32 | 0 | 未知，原样保留；工具拒绝非零变体 |

名称数组每项 u32，相对名称池；名称为 NUL 结尾 ASCII，按大写路径排序。
成员描述每项 0x18 字节：u64 绝对数据偏移、u64 数据字节数、u64 未知字段。
3471 个成员的未知字段全部为零，数据偏移均 0x200 对齐，无越界或重叠。
不能把未知字段称为压缩标记；本机有效载荷无需外层解压即可读取。

静态加载函数 `FUN_1402ee480` 先尝试 loose file，再挂载 rom.zar，规范化斜杠和大写后对名称做二分查找。
它按 `index * 0x18` 获取偏移、长度，支持当前工具的 TOC 重定位策略。
证据：`ev_32d9ec3a644884932efada7f68aaf28d89e670fc93aa9263b9653b76f23f653b`。
Loose-file 路径和所有调用模式的实际优先级尚未游戏验收，当前产物仍采用封包差分。

回写方式：完整保留原字节，把改变的成员追加到文件尾并按 512 字节对齐，只改对应 TOC 的偏移与长度。
未改变成员逐一比较字节，未知字段、名称和条目顺序均保留。
无修改回写在完整本机资源上得到相同 SHA-256。
`~INDEX` 是 VFS 的第二份资源目录，包含 3436 项；成员变长时必须同步更新对应长度。
格式：u64 数量，随后每项 `<u32 size, u32 flags, u64 name_offset>`，最后为 NUL 结尾名称池；名称偏移相对 `8+16*count`。
3435 项对应封包成员，另有外部 `/LICENSES.TXT`；后者保持不变。条目原顺序、路径和 flags 原样保留。
`FUN_1401ea990` 加载并重定位名称指针，`FUN_1401bc120` 把 size 写入 RomFile+0x68，
`FUN_1401ba2a0` 返回该长度；`FUN_1401bffe0` 据此分配和读取缓冲区。
此前“只更新 ZAR TOC 即可”的实验被实际启动日志证伪，详见 [启动修复](STARTUP_FONT_FIX.md)。

## 5. 字体与文本代码

**Verified / 静态：**初始化函数 `FUN_1400a72e0` 加载 `/fonts/d2font_12x15` 与 `/fonts/debug08`。
加载器 `FUN_1401109d0` 读取 `.json` 和 `.png`；解析器 `FUN_140110e00` 要求 `format=d1-rgba, version=1`。
字形键为十进制码点，转换后保留低 16 位。主字体原有 196 项。

JSON 主字段：cell_width=12、cell_height=15、layout_height=8、layout_top=5、linefeed=13。
字形字段：w/h/logw/xo/yo/tx/ty。原图集为 224×221 RGBA。
实验保留原字形及原图像像素，只追加所需字形。

**Verified / 静态：**`FUN_140111740` 按 16 位字符查询字形哈希表，未命中则查询码点 0。
`FUN_140111b60` 的宽度测量解码 UTF-8 1/2/3 字节序列，累加 `logw` 与字符间距。
`FUN_1400af860`（按钮刷新）以及 `FUN_1400b05c0`（文本绘制）包含相同的 BMP UTF-8 解码路径。
因此简体中文 BMP 码点具备代码路径依据，不必先对 EXE 注入 Hook。
这仍不等于中文画面已显示成功；四字节 UTF-8/增补平面字符暂不支持。

`FUN_1400b05c0` 对控制码 1..5 切换颜色，6..8 切换字体，10 换行，忽略 U+FEFF。
含切换到 debug08 的文本需要为对应字体单独补字，当前仅补主字体。
按钮结构中字体指针位于文本起点 +0x40，提示可能存在 64 字节内联文本容量；对应复制路径仍待定位，不能据此设置所有表格行的统一上限。
长文本测试矩阵只用于离线准备，不能直接当作已兼容菜单的产物。
